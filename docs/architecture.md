# 架构与第二阶段边界

## 0.5.0：独立斗地主模式

`scripts/doudizhu/` 与麻将核心、单机会话、LAN和场地规则隔离。`core/cards.gd` 使用独立的54张实体牌编码；`rules.gd` 是纯牌型与比较函数；`engine.gd` 管理发牌、叫分、出牌及本局零和计分；`ai.gd` 只消费指定座位的裁剪视图，不访问其他暗手或未公开底牌。

`session.gd` 在内存中运行一位真人和两位机器人的牌局。机器人计算在线程中进行，主线程以局标识、revision和座位核对结果，并等待出牌展示和语音结束。真人无倒计时；暂停不推进，退出回收工作线程；下一局清空本局计分，不限制局数。不写存档，也不改麻将的存档v1／v2／v3、重放或LAN协议3。

`ui/table.gd` 消费座位视图，接收选牌并发出动作；`ui/card.gd` 绘制独立矢量牌面；`audio/voice.gd` 用独立频道排队播放离线语音。`mode.gd` 负责它们之间的接线。现有 `app.gd` 仅增加入口、退出与系统返回／后台通知转发，进入斗地主时暂停麻将。两种游戏共用字体、美术、声音开关和SceneSurface显示基础，规则与计分不互相调用。斗地主尚不提供联机或退出后恢复。

0.6.0的`card.gd`换成LGPL传统牌图与mipmap采样；划选由牌桌统一接收本视口鼠标轨迹，冻结可见牌区并按线段与矩形交点补齐快移中的牌，每次手势每张仅切换一次。失焦、暂停和版本变化立即取消手势。

引擎新增公开的`played_cards`记录，只有接受的出牌才追加，过牌／重新领出不清空，每次发牌重置。`core/recorder.gd`仅用本席`hand`和该公开记录从54牌总量中扣除，得到各点数外部余牌；不读取暗手或额外扣除公开底牌。`ui/recorder.gd`提供可收起常驻显示。该字段不影响合法动作、计分或现有麻将存档。

男女声都使用完整60段离线音频；`DdzVoice.set_profile`停旧队列、加载新目录并保留动作去重标识，不补播旧动作。独立的`doudizhu_voice`偏好随现有偏好文件保存；QA仍不读写真人偏好，持久化回归注入独立临时路径。换声不改变对局revision或已选手牌。

0.6.1增加`ui/card_themes.gd`主题目录及`ui/theme_preview.gd`布局预览。「传统」可使用，「国风」是显式锁定的待素材选项；目录返回副本，UI和mode均检查可用性，`doudizhu_card_theme`偏好加载时将未发布／非法值归一到传统。预览弹窗暂停对局并保留选牌，关闭恢复原状态。主题不参与引擎、记牌器、存档或LAN协议，后续专属插画须完成接入与验证后显式发布。

## 第一阶段

`scripts/core/` 不引用场景树、UI、计时器或网络。Tiles 提供 0–41 牌种编码；Rules 是规则纯函数；GameEngine 是同步权威状态机；MahjongAI 只消费指定座位可见信息。

`scripts/session/local_session.gd` 是本机对局适配器。它驱动 AI 工作线程、控制表现节奏、存档和重放恢复。`scripts/app.gd` 和 `scripts/view/table_3d.gd` 只消费座位视图、呈现动作和接收输入。

Windows 的 `native/windows/` GDExtension 只处理本进程主窗口的原生移动／缩放消息：手势期间阻止 Godot 重入完整帧、延后尺寸同步，结束后同步一次。规则和存档仍由 GDScript 管理；拖动期间主循环暂停，已完成的动作保存不会被切成半次提交。`scripts/ui/scene_surface.gd` 将游戏场景与外层窗口隔离，保持原有逻辑坐标与输入路径。

每次请求包含 `seat + revision + action_id`。引擎只接受当前决策座位、当前版本和当次生成的合法动作，拒绝重复／过期／伪造请求。动画只展示结果，不参与发牌、判定和计分。

`GameEngine.view(seat)` 不包含牌墙、响应候选队列、其他未亮手玩家的手牌；其他玩家的暗杠也只保留张数，不泄漏牌面。AI 消费同样的视图。不会直接把 `snapshot()` 发给客户端；`snapshot()` 是权威端本地持久化数据，含完整牌墙及操作日志。

保存以临时文件写入，关闭句柄后替换，旧文件留备份。恢复时先校验完整牌墙，重新执行已接受动作，成功后再切换活动引擎；不直接相信保存的积分。

## 第二阶段：同一 Wi-Fi / 热点（0.2.0 已接入）

`LanSession` 继承本机会话接口，使用独立 `ENetMultiplayerPeer` 可靠 UDP 和有版本的 JSON 消息；房主运行现有 GameEngine，客人只提交本席的局号、版本和合法动作 ID。接收时校验身份、限制消息大小和处理频率。`SeatView` 将经过隐私裁剪的座位视图转换为本人在下方的 UI 视图。`LanDiscovery` 通过 UDP 查询及单播响应展示房间摘要，`LanLobby` 提供创建、浏览、地址加入、准备和房主设置。

已实现房间身份、入座准备、地址输入、心跳、进程内重连凭据和按席视图；安卓导出已开启网络权限。邀请二维码、相机、持久化确认、退出应用后的凭据／房主恢复仍未实现。真实 Windows／安卓混玩及热点广播需要设备验收；iOS／macOS 尚未完成本轮平台接入。详见 [附近同桌](lan-play.md)。

沿用旧项目的房间约定：

- 按 2026-11-04 本轮要求支持 1–4 真人，空位补 AI；客人准备后由房主开始。
- 创建时选择二五八将／乱将、吃牌开关、经典／牌效 AI；开局后固定。
- 每局轮庄，包括庄家胡牌或流局；无限续局、积分累计。
- 真人无出牌／响应倒计时；“空位 AI”和“掉线托管”分别处理。
- 掉线托管默认关闭，由房主开关；回归玩家收回控制，不应用过期 AI 结果。
- 进程存活时重连回原座位；房主从当前局日志恢复尚属后续目标，本版局域网不覆盖单机存档。
- 手机后台可能被暂停，不承诺房主退到后台后仍持续服务。首版不做房主迁移。

第三阶段再决定公网发现、穿透、中继或独立权威服务器。公网不是简单替换局域网 IP；规则核心和指令协议可复用，但连接与运营部分需另行实现。

## 0.3.0：独立场地规则

`settings.field_rules` 是与地方玩法、吃牌选项并列的布尔增强开关，默认关闭。`FieldRules` 保存稳定 ID、玩家文案与特殊牌型辅助；基础 `Rules` 通过可选 `field_id` 扩展胡牌／听牌／吃牌和计分，空 ID 保持正常模式。当前基础玩法仍只有山东麻将。

权威引擎每局等概率抽取一项，记录于 `opening.field_id`；每席分别保存能力用量。交换牌先收集四席选择再统一移动，普通摸牌三选一使用 `draw_choice`／`gift_choice` 阶段。所有新动作仍校验座位、版本与动作 ID，不信任客户端提交牌值。旧正常存档继续 v1，场地存档 v2；恢复只重放校验过的开局牌组与合法日志，重建能力次数、透明实体属性和积分，不信任序列化后的状态。

`GameEngine.view(seat)` 隐去牌山、换牌选择和他家的 `field_private`。透明场地只公开实体明牌，暗牌槽集中展示，避免私有排序泄露暗牌范围；新摸槽单独保留。变白事件不带原牌，牌量只增加白板公开上限，不公布缺失牌种。无字天书公开初始牌组各牌面总量。`SeatView` 同时旋转私有占星目标与合法动作的目标座位。

LAN 会话与发现协议均为 2；与旧协议客户端显式拒绝混玩。机器人只消费本席裁剪后的视图，场地策略使用牌效启发式，合法性始终由权威引擎判定。

## 0.4.0：指定场地与摸后追加

`field_rules` 仍负责开关，`field_selection` 保存 `random` 或稳定场地ID；关闭时保留选择。单机与LAN共用 `FieldRules.normalize/selection/summary`，固定选择随续局保留，非法本机配置回退随机，收到的非法网络配置拒绝。新v3存档中固定选择须与实际 `opening.field_id` 一致。

新天使流程不再进入 `draw_choice`，普通摸牌先完成为 `turn`，只在该次出牌前提供可选 `field_gift`。引擎记录该实体牌的墙槽，发动时将原摸牌和山前两张暂存在私有候选池，手牌退回基础张数；选完后两张未选牌按原候选顺序放回牌山前端，实体墙槽同步回收。候选池属于物理牌总量，不能同时计在手牌或牌山中。私有候选与内部墙槽不会发给其他席，UI预览只使用本席视图。

场地新存档版本3，普通模式仍为1。恢复旧v2场地时保留原 `draw_choice` 和动作编号；`tests/fixtures/replay-field-v2-gift.json` 在改动前由0.3.0引擎生成，覆盖发动前、选择中、选择后三个真实旧状态。新局才改用摸后追加，避免以新流程误解旧日志。LAN／发现升级到协议3，所有玩家需同步更新。

## 0.8.0：独立扑克玩法与共享牌面

`scripts/bluff/` 独立实现唬牌核心、机器人、会话、声音和界面，通过 `mode.gd` 接入大厅；不依赖麻将或斗地主的规则／会话。3–6 人、双牌组以 0–107 的实体编号区分；裁剪视图仅给本家手牌、公开张数／宣言以及最近一次被质疑的牌。死牌和历史堆牌不公开。核心 `rps → review → playing → review/finished` 转换由动作驱动，复核画面等待真人，不依赖动画计时推进规则。

会话控制机器人停顿和音频展示，真人动作携带局号与版本防止旧局回调。`preferences.json` 中只有独立 `bluff_settings`，没有唬牌存档；旧麻将重放格式和 LAN 协议不变。`tests/bluff_session_test.gd` 验证切换玩法前后麻将状态与存档字节不变且仍能恢复。

扑克绘制与主题目录提取到 `scripts/poker/ui/`；斗地主原 `ui/card.gd`、`ui/card_themes.gd` 为兼容入口，既有牌值规则没有变化。唬牌只共用该展示层与既有资源文件，避免重复复制牌图。新语音运行时独立，生成工具复用本机已有开放模型缓存，游戏包仅包含有来源清单的 WAV。

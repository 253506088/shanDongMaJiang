## 山东玩法迁移基准

用户确认的是沿用旧工程当前山东实现。下列具体条目来自旧代码、文档和已经完成的迁移核对：

- 144 张牌：136 张常规牌和 8 张花牌；初始 2000 分，底分 10。
- 二五八将／乱将、是否允许吃牌。
- 庄家 14 张、闲家 13 张，起手补花；公开杠头。
- 摸打、吃、碰、明杠、暗杠、补杠、抢杠胡。
- 普通胡牌前需报听或明搂；声明针对实际弃牌验证听口。
- 报听／明搂后锁手；明搂亮手、只可自摸，并按原规则处理赢输倍数。
- 过胡、过碰到本人再次摸到普通牌解圈；单响截胡和应牌优先级。
- 天胡、地胡、海底、八花、特殊牌型、花分和番型叠加。
- 自摸、点炮、抢杠和明搂付款方式保持迁移基准。
- 每局轮庄；局域网模式按旧房间规则无限续局。

旧实现中的特定判定及已知不寻常行为已经记录，包括南风花色识别、带杠组合的部分花色判断和八花计分。后续不能把“改界面”或“整理文档”顺带变成另一套玩法。若另行修订规则，应同步更新规则说明、参考牌例和必要的存档版本。

完整技术定义及已做的操作调整见 [规则基线](../docs/rule-baseline.md)。

## 第一阶段的具体体验

以下是当前第一阶段已经采用的实现范围，来自方案和已落地工程：

| 部分 | 内容 |
| --- | --- |
| 开局 | 一名真人与三名电脑；选择将牌、吃牌、AI 和场次 |
| AI | 经典和牌效两种模式；以本席可见信息决策，计算不阻塞画面 |
| 场次 | 东风 4 局、半庄 8 局、自由续局；轮庄并累计积分 |
| 交互 | 鼠标／触屏选牌与出牌，吃碰杠胡提示，报听／明搂入口，牌效建议 |
| 画面 | 3D 牌桌、牌墙、牌面和骰子，动作提示、胡牌演出、结算展示 |
| 续玩 | 自动存档、备份回退、暂停、关闭后恢复、牌谱导出 |
| 设置 | 声音、画质、电脑行牌速度；本家可交给 AI 托管并收回 |

当前原生界面以横屏为主。用户尚未提出竖屏独立布局、角色养成、多主题商城或大模型联网 AI 等新增产品要求。

## 第二阶段的房间行为

这些条目来自用户“先搬运旧项目建房规则”的要求及旧项目行为记录，作为局域网阶段的迁移目标：

| 部分 | 约定 |
| --- | --- |
| 网络场景 | 同一 Wi-Fi 或手机热点；基本同桌对局不依赖公网服务 |
| 人数 | 2–4 位真人，空位补普通 AI |
| 开始 | 入座、准备后，由房主开始 |
| 房间设置 | 将牌、吃牌开关、经典／牌效 AI；开局后固定 |
| 行牌 | 真人无出牌、应牌或续局倒计时 |
| 续局 | 每局结束均轮庄，包括庄家胡牌和流局；无限续局、积分累计 |
| 掉线 | 保留原座位；默认关闭掉线托管，由房主控制开关 |
| 恢复 | 回归玩家收回控制，过期 AI 决策不覆盖真人操作 |
| 房主恢复 | 从当前局日志恢复，不能重复扣分或重复结算 |
| 邀请与加入 | 迁移旧房间的邀请／扫码加入体验，并提供可用的备用加入方式 |

当前技术设计以房主设备运行权威牌局为基础。原 Android Java 传输实现和旧平台 SDK 不要求原样照搬到 Godot；Godot 侧协议、传输方式和跨端平台接入尚待第二阶段落实。

## 为联网预留的实现约束

这是当前设计采用的工程边界：

- 规则、回合、计分与 UI、动画分离。
- 玩家和 AI 通过动作请求参与对局；引擎校验座位、版本和合法选项。
- 每个座位只得到自己可见的状态；隐藏牌墙、他人暗手及对手暗杠牌面。
- 动画展示规则结果，不靠动画完成回调决定规则是否合法。
- 本地完整存档与发给玩家的视图分开；完整牌墙不能直接广播。
- 单机适配器与未来局域网适配器尽量共用规则核心和表现接口。

现有结构见 [架构文档](../docs/architecture.md)。预留这些边界不等于局域网传输和建房已经实现。

## 美术、启动与仓库交付

用户允许寻找开源素材，或由助手提供提示词、用户协助生成图片。当前首版已具备可运行的原创程序化美术与音效，不依赖用户先补图；进一步提升风格可作为后续打磨。

根目录需要保持两个入口：

- `启动游戏.bat`：优先运行 Windows 构建；没有构建时自动导入资源并运行源码。
- `打包游戏.bat`：选择 Windows、Android、macOS 或全部，显示打包结果与错误，输出到 `build/`。

源码、必要素材、许可、测试数据、文档和构建脚本进入 Git。导出程序、安装包、导入缓存、临时下载、截图、日志、凭据和签名私密文件排除，并在 `.gitignore` 中注明。
